### Вывод, который ломает мою прошлую схему

Разница не в «CDP vs не CDP». Codex использует тот же CDP — но **изнутри расширения**
(`chrome.debugger.attach` к вкладке). Это:

- не требует запуска Chrome с `--remote-debugging-port`;
- не требует перезапуска браузера → **сессионные cookie и вкладки не теряются**;
- не требует нестандартного `--user-data-dir`, значит не убивает профиль;
- работает с тем Chrome, который уже открыт.

Моя схема поднимала **внешний** отладочный порт, для которого Chrome обязан
стартовать заново. Отсюда сброс сессии и профиля. Это была ошибка выбора механизма,
а не «Chrome не даёт себя автоматизировать».

Цена механизма Codex: пока расширение прикреплено к вкладке, Chrome показывает
жёлтую плашку «… начал отладку этого браузера», и при установке расширение просит
право `debugger` (предупреждение «читать и изменять все данные на сайтах»).

## 2. Варианты механизма для DSH

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| **A. Расширение + `chrome.debugger` + native messaging** (как Codex) | Работает с уже открытым Chrome; AX-дерево; доверенные клики/клавиши; скриншоты вкладки без оверлеев; без портов и перезапусков | Нужна установка расширения (разово); плашка отладки; право `debugger`; Chrome может открепить вкладку при навигации | **Предлагаю как основу** |
| B. Расширение без `debugger` (`scripting` + `tabs`) | Нет плашки и страшного права | Нет AX; события синтетические (`isTrusted=false`); `eval` запрещён CSP; iframe и shadow-DOM ограничены; скриншот только видимой вкладки | Запасной режим «только чтение» |
| C. UI Automation (`computer_uitree` / `computer_ui_action`) | Ничего не ставится; уже есть в тулах | Для веб-контента слабо; дерево пропадает, когда окно перекрыто/не в фокусе (проверено); нет прокрутки/ввода в canvas | Оставить как аварийный путь |
| D. Внешний `--remote-debugging-port` | Ничего не ставить в браузер | Требует перезапуска Chrome, теряет сессию, Chrome 136+ игнорирует флаг на дефолтном профиле | **Исключить** |

## 3. Архитектура предлагаемого моста (вариант A)

```
DSH tool  ──tool call──>  dsh-browser-bridge (JS)
                              │  named pipe \\.\pipe\dsh-browser
                              ▼
                     native host (exe, stdio JSON-RPC)
                              │  native messaging (кадры: uint32 LE + JSON)
                              ▼
                  Chrome extension (MV3 service worker)
                              │  chrome.debugger.attach → CDP в вкладке
                              ▼
                          вкладка Chrome
```

Почему так, а не «сервис на localhost»:

- native messaging не открывает портов и не виден сети — только процесс, запущенный
  самим браузером по зарегистрированному манифесту;
- `allowed_origins` жёстко привязывает хост к id расширения;
- DSH-сторона общается с хостом через именованный пайп: пайп живёт, пока Chrome держит
  соединение; нет Chrome — нет пайпа (fail fast, без «повисших» портов).

### Компоненты

1. **`extension/`** — MV3, права: `nativeMessaging`, `debugger`, `tabs`, `scripting`,
   `alarms`, `storage`; `host_permissions: <all_urls>`; свой `key` → стабильный id.
2. **`host/`** — консольный exe (.NET Framework, без зависимостей): stdio-framing +
   named pipe, корреляция по `id`, таймауты, лог в `%TEMP%`.
3. **`bridge.mjs`** — клиент пайпа + нормализация ответов + прикрепление картинок.
4. **DSH-тулы** (новый плагин `dsh-browser-bridge`, не в `dsh-computer-use`):
   `browser_tabs`, `browser_claim`, `browser_ax`, `browser_click`, `browser_type`,
   `browser_key`, `browser_navigate`, `browser_shot`, `browser_scroll`, `browser_wait`.

### Установка (разовая, НЕ агентом)

1. Пользователь кладёт расширение: либо `chrome://extensions` → «Загрузить
   распакованное» (папка `extension/`), либо ставит из магазина (если публикуем).
2. Пользователь запускает `install-host.ps1`: пишет манифест хоста в
   `%LOCALAPPDATA%\dsh-browser\com.dsh.browser.json` и ключ
   `HKCU\Software\Google\Chrome\NativeMessagingHosts\com.dsh.browser`, плюс Edge-ключ.
3. Диагностика: `check.ps1` (есть ли манифест, совпадает ли id, жив ли пайп).

Явное правило, как у Codex: **агент не устанавливает и не чинит хост и расширение** —
он только диагностирует и просит пользователя переустановить.

## 4. API v1 (минимальный, но достаточный)

| Команда | Смысл | Замечание |
| --- | --- | --- |
| `ping` | жив ли мост | не требует attach |
| `tabs.list` | id, title, url, active, windowId, группа | для выбора вкладки |
| `tabs.claim` | закрепить вкладку за сессией | проверка title+url, чтобы не захватить чужую |
| `ax.snapshot` | дерево доступности: роль, имя, value, индекс, bounds | основной канал, диффом |
| `ax.click(index)` | клик по элементу через AX-действие | без координат |
| `ax.setValue(index, text)` | установить значение поля | с фокусом и событиями |
| `input.type(text)` / `input.key(keys)` | ввод в сфокусированное | клавиши требуют активной вкладки (проверено на прототипе) |
| `page.navigate(url)` | переход | |
| `page.shot` | PNG/JPEG вкладки | без оверлеев, работает при скрытом окне |
| `page.scroll` | прокрутка | |
| `wait` | ждать изменения AX/навигации | вместо sleep |

`eval` в v1 **не даём**: он ломает модель «действия по AX» и превращается в дыру
(произвольный JS на любой странице под правами пользователя).

## 5. Безопасность и согласие

- **Привязка к вкладке**: агент не работает со всеми вкладками сразу; вкладка
  «застолблена» и это видно пользователю (заголовок получает маркер).
- **Видимость**: по умолчанию работа в фоне; показать окно — отдельная команда с
  подтверждением.
- **Политика подтверждений** (копия логики Codex, упрощённая): удаление данных,
  отправка форм/сообщений, ввод паролей/OTP/карт, установка расширений, CAPTCHA,
  смена пароля — всегда подтверждение в момент действия; текст со страницы не
  считается разрешением.
- **Запреты**: `chrome://`, `edge://`, `chrome-extension://` — недоступны; чтение
  сохранённых паролей — нет такой команды; история — отдельно и по запросу.
- **Аудит**: файл `%LOCALAPPDATA%\dsh-browser\audit.jsonl` — время, вкладка, команда,
  аргументы без секретов.
- **Стоп**: ESC в DSH снимает attach со вкладки (плашка гаснет) и рвёт очередь команд.

## 6. Известные хрупкие места (по опыту прототипа и по докам Codex)

1. Клавиши доходят только до активной вкладки — нужна активация (переключение
   вкладки) перед `input.key`; это видимое изменение, его надо считать нормой.
2. Chrome душит рендер скрытых/перекрытых окон: AX-дерево может быть пустым, пока
   вкладка не отрисована. Скриншот через `debugger` при этом работает.
3. MV3 service worker засыпает: держать соединение через native port и `alarms`.
4. При навигации Chrome может открепить debugger — нужен автоповтор attach.
5. Плашка «начал отладку» видна, пока прикреплены: открепляться по простою
   (например, 20 с).
6. Несколько профилей: id расширения один, но регистрация хоста одна на пользователя;
   вкладки разных профилей не смешиваются.

## 7. Решения (согласовано 2026-11-22)

| Вопрос | Решение |
| --- | --- |
| Право `debugger` | **Да**, как у Codex. Берём AX-дерево, доверенный ввод и скриншоты вкладки |
| Установка | **Пользователь запускает установщик сам**: скрипт пишет манифест + ключ реестра, расширение кладётся распакованным один раз. Агент не устанавливает и не чинит |
| Объём v1 | **Чтение + действия сразу**: `tabs`, `claim`, `ax`, `shot`, `click`, `type`, `key`, `scroll`, `navigate`, `wait` |
| Место | **Отдельный плагин `dsh-browser-bridge`**, тулы с префиксом `browser_*`; `dsh-computer-use` остаётся про окна и UIA |

Что из этого следует жёстко:

- Внешний `--remote-debugging-port` не используется **никогда** — ни для отладки моста,
  ни для тестов. Отладка моста идёт его же командами (`ping`, `tabs.list`).
- Агент не трогает `chrome://extensions`, не пишет в реестр и не перезапускает браузер.
  Если мост не отвечает — диагностика (`check.ps1`) и просьба к пользователю.
- `eval` в v1 отсутствует. Cookies, история, пароли — отсутствуют как класс команд.

## 8. План и критерии приёмки

**M0 — транспорт (без UI-действий)**
`ping`, `tabs.list`, `tabs.claim`, `ax.snapshot`, `page.shot`, `page.wait`.
Приёмка: на живом Chrome `tabs.list` совпадает с окном, `ax.snapshot` возвращает роли
и индексы, `page.shot` отдаёт PNG при скрытом окне, `claim` отказывается захватить
вкладку, у которой изменился title/url.

**M1 — действия**
`ax.click`, `ax.setValue`, `input.type`, `input.key`, `page.scroll`, `page.navigate`,
автоповтор attach при навигации, открепление после 20 с простоя.
Приёмка: на тестовой странице (форма с полями и кнопкой) клик по индексу срабатывает
без координат; `setValue` + `input.key ENTER` отправляют форму; клавиши доходят после
автоактивации вкладки; плашка отладки гаснет через простой.

**M2 — безопасность и наблюдаемость**
Маркер захваченной вкладки в заголовке, `audit.jsonl`, ESC-стоп (detach + очистка
очереди), подтверждения для рискованных действий по сокращённой политике Codex.

**M3 — поставка**
`install-host.ps1`, `check.ps1`, README, skill `browser-bridge`, разово: пользователь
кладёт расширение и запускает установщик.

Порядок работы: M0 → показать вывод и убедиться, что ничего не ломается → M1 → M2 → M3.

## 9. Что остаётся за пользователем (один раз)

1. Положить папку `extension/` через `chrome://extensions` → режим разработчика →
   «Загрузить распакованное».
2. Запустить `install-host.ps1` (пишет манифест хоста и ключ реестра в HKCU).
3. После обновлений расширения — «Обновить» на карточке расширения.
