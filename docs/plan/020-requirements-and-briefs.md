# Требования и рабочие брифы

## Часть A. Требования

### A1. Функциональные

| ID | Требование | Проверка |
|---|---|---|
| F1 | Перетаскивание дивидера изменяет ширину правой панели 1:1 за курсором | ручной драг + self-test: ширина в кадре = позиции курсора (±2 px) |
| F2 | Ширина ограничена: min 340 px, max `min(720, 75%·(innerWidth−sidebar))` | тест на узком/широком окне |
| F3 | Двойной клик по ручке — сброс на 340 px | self-test |
| F4 | Клавиатура: ←/→ ±8 px, Shift ±32 px, Home 340, End max, Enter — переключение 340↔max | self-test |
| F5 | Ширина сохраняется между запусками | перезапуск приложения |
| F6 | Esc/blur/resize/потеря захвата отменяют драг без «прыжка» ширины | self-test с имитацией отмены |
| F7 | Молния на отпускании работает и не влияет на движение | визуально + метрики |
| F8 | Во время драга текст чата не пере-шейпится покадрово | A/B метрики `layout`/`render` |
| F9 | Артефакт в панели (в т.ч. `<video>`) не перезапускается при драге | ручной тест с mp4 |
| F10 | Профайлер по требованию выдаёт отчёт было/стало | одна команда |

### A2. Нефункциональные (пороговые)

| ID | Метрика | Порог |
|---|---|---|
| N1 | Медиана межкадрового интервала во время драга | ≤ 33 мс |
| N2 | p95 межкадрового интервала | ≤ 50 мс |
| N3 | Кадры > 100 мс в окне драга (приложение не стримит) | 0 |
| N4 | `layout` на кадр во время драга | ≤ 5 мс |
| N5 | `render` на кадр во время драга | ≤ 16 мс |
| N6 | Один кадр коммита после отпускания | ≤ 100 мс |
| N7 | Утечки: анимации/стили после драга | 0 залипших `paused`, 0 `content-visibility` |

### A3. Ограничения и запреты

- GUI — одна веб-страница: нативные view Claude недоступны; ближайший аналог — `<iframe>`.
- Нельзя вешать обработчики, ломающие нативный драг приложения (окно/панель вне нашего контроля).
- **Запрещено**: `content-visibility: hidden` на чате, `contain: paint` на транскрипте,
  глобальные `*`-стили на время драга — всё это уже приводило к поломке виртуализации.
- Конфиг профиля и app.asar — только чтение; правки через клиент/плагин.
- Секреты и тексты сообщений в логи не пишем.

### A4. Приёмка стори

Стори закрыта, когда: (1) все её таски выполнены, (2) сняты метрики до/после,
(3) приложен отчёт self-test, (4) нет регрессий по N7, (5) обновлён baseline в S4.

## Часть B. Брифы

### B1. Бриф S1 — дивидер без анимации

**Контекст.** Сейчас `createMotionPort` запускает три WAAPI-анимации по `grid-template-columns`,
`width`, `left`. Каждая — layout-инвалидатор; на кадр приходится три инвалидации
и полный ре-лейаут приложения.

**Решение (по образцу Claude).**

1. При `pointerdown` запоминаем стартовую ширину и `clientX`; фокус-стили на `body`.
2. На `pointermove`: `next = clamp(startWidth + (startX - clientX))` (учёт RTL — по `dir`);
   одна запись: `frame.style.setProperty('--dsh-panel-w', next + 'px')`.
3. Разметка потребляет переменную: `grid-template-columns: <sidebar>px minmax(400px,1fr) minmax(0px, var(--dsh-panel-w))`;
   ширина панели и `left` ручки — через `calc(var(--dsh-panel-w))`.
4. `pointerup`: `bridge.commit(next)` (нативное состояние), молния, сохранение ширины.
5. Клавиатура/двойной клик — как в F3/F4.
6. Никакой анимации ширины; анимация молнии остаётся анимацией эффекта и живёт на canvas/SVG.

**Технические заметки.**

- Проверить, не перетирает ли React inline-стиль панели нашу переменную: у панели
  остаётся `width`, у frame — переменная; при конфликте писать в тот же `style` через
  `setProperty` с приоритетом не выше inline React-стиля.
- Сохранить существующие предохранители: `nativeStamp`, `bridge.valid`, ACK-проверка,
  отмена по resize/blur/Esc.
- Убрать `MOTION_PARTS` и elastic-easing — они больше не нужны.
- `MOVE_DIAG` оставить (стоимость одной паузы анимаций), `MOVE_PROFILE` — как мера.

**Тесты.** 5 self-тестов подряд: `MOVE_PROFILE` p50/p95/max; ручной драг в тишине;
проверка клавиатуры и двойного клика; сохранение ширины после перезапуска.

**Ожидание.** N1–N3 выполнены; визуально — «панель в руке», без догоняющей анимации.

### B2. Бриф S2 — чат не переобтекает во время драга

**Контекст.** Транскрипт — колонка `1fr`; её ширина меняется каждый кадр, поэтому Chromium
пере-шейпит текст. `layout` при этом всего 5–30 мс, а `render` 200–400 мс — то есть дорогая
именно перерисовка уже пере-шёпленного текста.

**Решение (вариант Claude).**

1. Ввести контентную колонку: сообщения живут в блоке с `max-width: min(100%, <C>)`,
   центрированном (`margin-inline: auto`), где `C` подбирается по замеру (старт 720 px).
2. Во время драга контейнер меняет ширину и **клипает** (`overflow: clip`), внутренняя
   колонка сохраняет прежнюю ширину (`width: <старая>px` на время драга), затем снимается.
3. Запрещено использовать `content-visibility` и `contain` на транскрипте.

**Тесты.** A/B по 5 драгов на длинном чате: `render`, `layout`, число кадров; два скриншота
(во время и после). Проверить на коде, таблицах, изображениях и на узком окне.

**Ожидание.** N4–N5; после отпускания один кадр ≤ N6 без видимого «прыжка».

**Риск-план.** Если `max-width` визуально неприемлем, оставить ширину колонки как есть, но
на время драга фиксировать её текущее значение и клипать контейнером (это уже делали —
не сработало из-за `contain: paint`; повторить без него).

### B3. Бриф S3 — артефакт не участвует в рефлоу

**Контекст.** Артефакт — `<iframe>`; при драге мы покадрово меняем его размер, что
перезапускает медиа и стоит кадров.

**Решение.**

1. Контейнер панели получает `contain: paint` (только он, не чат).
2. Во время драга размер iframe **не меняется**: контейнер клипает по новой ширине.
3. На `pointerup` — один раз выставить размер iframe (`width/height`), затем снять клип.
4. Для `<video>`: не трогать `src`, не пересоздавать элемент; проверить сохранение `currentTime`.

**Тесты.** Self-test с открытым mp4: кадры, `currentTime` до/после, отсутствие «мигания».

**Ожидание.** Нет кадров > 50 мс в окне драга; видео продолжает играть.
