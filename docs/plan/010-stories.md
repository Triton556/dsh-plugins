# Стори и таски: производительность GUI DSH по образцу Claude

Порядок — обязательный: каждая стори опирается на инструменты предыдущей.
«Готово» = выполнены все критерии приёмки; без них стори не закрывается.

---

## S0. Инструменты наблюдения (закрыто, поддержка)

**Цель:** уметь видеть, измерять и повторять драг без участия человека.

| # | таска | ожидаемый результат |
|---|---|---|
| T0.1 | CUA-тулкит: `windows/tabs/tab/focus/shot/uitree/find/hit/click/drag/type/scroll` | могу сфокусировать любое окно и вкладку Chrome, кликнуть, потянуть, напечатать |
| T0.2 | `asar.mjs` (list/grep/extract) | читаю код любого Electron-пакета локально |
| T0.3 | Vision | скриншот читается моделью (`read_image`), проверено на окне DSH |
| T0.4 | Self-test драга через файл-счётчик | драг воспроизводится из PowerShell, метрики в логе |

**Приёмка:** скриншот окна читается; вкладка Chrome выбирается по названию; драг из скрипта
даёт `DRAG/SCAN/MOVE/ACK/SETTLED` в `divider-diag.log`.

**Осталось (по мере надобности):** OCR (`Windows.Media.Ocr`) как fallback, снимок области,
JSON-вывод списка окон.

---

## S1. Дивидер: прямая манипуляция вместо анимации

**Цель:** перенести модель Claude — ширина следует за курсором, один инвалидатор layout.

| # | таска | детали |
|---|---|---|
| T1.1 | Убрать WAAPI-анимацию ширины | `createMotionPort` больше не анимирует `grid-template-columns`/`width`/`left` |
| T1.2 | Один источник истины | писать `--dsh-panel-w` на корневой frame; grid-трек, ширина панели и `left` ручки выводятся через `calc(var(--dsh-panel-w))` |
| T1.3 | Запись на `pointermove` | без rAF-цикла: одно `style.setProperty` на событие (Chromium сам схлопывает до кадра) |
| T1.4 | Коммит на `pointerup` | React-состояние и сохранение ширины — только на отпускании (как сейчас) |
| T1.5 | Поведение как у Claude | min 340, max `min(720, 75%·(innerWidth−sidebar))`, dblclick → 340, стрелки ±8/±32, Home/End, Enter |
| T1.6 | Совместимость | сохранить: отмену по Esc/blur/resize, валидацию `nativeStamp`, один commit, ACK-проверку, молнию на отпускании |

**Ожидаемый результат (измеримо):**
- `MOVE_PROFILE`: медиана gap ≤ 33 мс, p95 ≤ 50 мс на нашем стенде (сейчас 100–400 мс);
- нет кадров > 100 мс в окне драга, когда приложение не стримит;
- визуально: панель следует за курсором 1:1, без «догоняющей» анимации;
- поведение клавиатуры/сброса совпадает с Claude.

**Приёмка:** серия из 5 self-тестов подряд + один ручной драг в тишине; цифры и скриншот.

**Риски:** наш нативный обработчик уже пишет ширину сам — нужно убедиться, что мы не
дублируем запись (возможен конфликт с React-стилем). План: переменная на frame + `!important`
не использовать; при конфликте — писать в тот же inline-стиль, что и React.

## S2. Переобтекание чата: убрать главный `render`

**Цель:** при драге текст не пере-шейпится; перестройка — один раз в конце.

| # | таска | детали |
|---|---|---|
| T2.1 | Замер базовой линии | открытый длинный чат, self-test, фиксируем `render`/`layout` |
| T2.2 | Контентная колонка с `max-width` | как у Claude: сообщения в столбце ограниченной ширины, центрированном |
| T2.3 | Драг-режим: клип вместо ре-лейаута | внешний контейнер меняет ширину и клипает; внутренняя колонка сохраняет ширину |
| T2.4 | Коммит перестройки | после `pointerup` один reflow, без видимого «прыжка» (проверить на коде и таблицах) |
| T2.5 | Сравнение A/B | с фиксом и без; отчёт в логе |

**Ожидаемый результат:**
- во время драга `layout` ≤ 5 мс, `render` ≤ 16 мс на кадр (сейчас 200–400 мс);
- после отпускания один кадр ≤ 100 мс;
- текст не «пляшет» и не обрезается в середине слов;
- на узком окне (< 900 px) поведение не хуже текущего.

**Приёмка:** A/B по 5 драгов, одинаковый контент, приложены метрики и два скриншота.

**Риск:** `content-visibility`/`contain` уже один раз ломали виртуализацию — этот вариант запрещён.
Использовать только `max-width` + клип контейнера.

## S3. Артефакты: панель вне рефлоу

**Цель:** ресайз с открытым артефактом (в т.ч. видео mp4) не портит кадры и не перезапускает медиа.

| # | таска | детали |
|---|---|---|
| T3.1 | Замер с открытым артефактом | self-test при открытой вкладке артефакта, зафиксировать стоимость |
| T3.2 | Стабильный слой | `contain: paint` на контейнере панели; iframe не меняет размер во время драга — клипается контейнером |
| T3.3 | Медиа | проверить, что `<video>` не перезапускается и не теряет позицию |
| T3.4 | Коммит размера | после `pointerup` один раз выставить размер iframe |

**Ожидаемый результат:** нет кадров > 50 мс в окне драга при открытом видео; плеер не дёргается;
после коммита артефакт занимает точный размер.

**Приёмка:** self-test с открытым mp4 + скриншоты до/во время/после.

---

## S4. Постоянный профайлер и защита от регрессий

| # | таска | детали |
|---|---|---|
| T4.1 | Оставить self-test триггер | файл-счётчик → окно; не влияет на прод-поведение |
| T4.2 | Метрики в отчёт | p50/p95/max по gap, `render`, `layout`, число кадров |
| T4.3 | Эталон | файл с baseline, сравнение при каждом прогоне |

**Ожидаемый результат:** одна команда даёт отчёт «было/стало» и pass/fail по порогам.

---

## S5. Vision-QA (опционально, после S1–S3)

Скриншоты ключевых состояний + сравнение с эталоном: панель до/после, артефакт, composer.
Цель — ловить визуальные регрессии, которые не видны в цифрах.

---

## Порядок и зависимости

```
S0 (готово) → S1 (дивидер) → S2 (чат) → S3 (артефакты) → S4 (регрессии) → S5 (опц.)
```

S1 и S2 независимы по коду, но S2 измеряется только после S1: сейчас джанк маскирует
вклад переобтекания.
