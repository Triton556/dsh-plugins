# Отложенные команды артефактов (невидимая сессия)

Статус: реализовано 2026-11-26. Отчёт о живой проверке — в конце.

## Задача

`dsh_artifact_open` из сессии, которую пользователь сейчас не видит, отвечал
`CLIENT_STALE` и ничего не открывал. Причина проверена по коду: клиент панели
(`createRuntimeCoordinator`, `tools/coordinator.js`) существует только у
смонтированной сессии; при переключении чата рантайм останавливается, heartbeat
(`client.js`, интервал 1.5 с, лимит 6000 мс) пропадает, а `CommandBroker.submit`
(`tools/bridge.js`) требовал живого клиента **в момент вызова** и отказывал, хотя
очередь и `poll()` в брокере уже были.

## Рассмотренные варианты

1. **Файловый мост** (`.dsh/artifact-panes/open-request.json`, прежний
   `openWithoutClient`). Писатель живёт на хосте, но читатель — тот же
   ненасмонтированный клиент видимой сессии: для скрытой сессии чтения не
   происходит. Отклонён как основной путь, остался как исторический канал для
   видимой сессии.
2. **Очередь в памяти хоста с отложенным исполнением** — выбран. Хост уже знает
   capability и очередь команд; клиент при монтировании сразу вызывает `poll()`,
   поэтому запрос исполняется без участия агента.
3. **Разрешать команды без клиента и «притворяться applied»** — отклонён: вкладки
   нет, это ложь в контракте.

## Контракт

- Откладываются только команды с устойчивым адресом: `dsh_artifact_open`,
  `dsh_ui_panel_open{kind:"artifact"}`, `dsh_artifact_close`. Закрытие адресуется
  `tabId`, а не лицензией документа.
- Скрытая сессия: `ok: true`, `effect: "none"`, `data: {queued: true, pending: true,
  commandId, position, expiresAt}`; `context.tabId` пуст.
- `dsh_artifact_tabs`: при живом клиенте — открытые вкладки (`pending: false`) плюс
  строки очереди (`pending: true`, `position`, `expiresAt`); при скрытой сессии —
  `live: false` и только очередь. Открытые вкладки скрытой сессии хосту неизвестны,
  и врать о них нельзя.
- Документные команды (`act`, `query`, `wait`, `navigate`, `screenshot`,
  `ui_panel_tabs`, `ui_panel_open` остальных видов) при скрытой сессии отвечают
  `ok: false`, `error.code: "SESSION_NOT_VISIBLE"`, `effect: "none"` — быстро, без
  ожидания. Это записано и в описания инструментов.
- Лимиты: `LIMITS.deferred` = 10 минут на ожидание, `LIMITS.queue` = 32 команды на
  сессию, `LIMITS.grace` = 2.5 с. Очередь — только в памяти процесса.
- Путь валидируется `resolveArtifact` в момент постановки; отложенная команда не
  получает новых прав и открывает только артефакт своего воркспейса.
- Повтор того же пути/вкладки схлопывается в один запрос (одинаковый `commandId`).

## Механика

- `tools/bridge.js`: `live()`, `pending()`, `rows()`, `queuedResult()`,
  `enqueue()` (постановка без ожидания, дедупликация, предел), `submit({defer})`
  (живой клиент — как раньше; скрытый — сразу в очередь), `expire()` (льготное
  окно превращает недоставленную отложенную команду в `queued` и продлевает
  TTL), `poll()` (доставка начинает свежее окно исполнения и помечает команду
  `deferred: true`), `receipt()` (для `deferred` закрытия документ сверяется по
  `tabId`), `bye()`.
- `tools/client.js`: при размонтировании `stop()` шлёт `op: "bye"` (keepalive):
  хост сразу считает клиента ушедшим, недоставленная отложенная команда
  возвращается в очередь, начатая завершается `UNKNOWN_EFFECT` без переигровки.
  Закрытие отложенной команды выполняется по `tabId`, документ не требуется.
- `tools/host.js`: `deferrable()` маршрутизирует три вида команд, `tabsWithQueue()`
  добавляет очередь в `tabs`, `hiddenSession()` переводит `CLIENT_STALE` в
  `SESSION_NOT_VISIBLE` для остальных. Файловый `openWithoutClient` удалён.
- `tools/contracts.js`: `LIMITS.deferred`/`grace`, `DEFERRED`/`deferrable()`, новые
  описания инструментов.
- Генератор `tools/codex-worker/build-tools-v1.mjs` теперь также переписывает два
  сгенерированных региона `client.js` (пакетированный рантайм и строку
  `ARTIFACT_TOOLS_DISPATCHER_SOURCE`), поэтому бандлы не расходятся с
  `tools/*.js`.

## Отказы и предельные случаи

- Маячок `bye` потерян (перезагрузка страницы, падение рендерера): работает
  льготное окно 2.5 с — вызов всё равно вернёт `queued`, а не ошибку; TTL 10 минут
  остаётся страховкой.
- Клиент перемонтировался между `poll` и `receipt`: старый инстанс не может
  отчитаться (`STALE_COMMAND`), команда либо в очереди, либо уже завершена.
- Сессия закрыта целиком: запрос истечёт по TTL и исчезнет из `tabs`; вкладку
  открыть некому — это честно видно по `expiresAt`.
- Перезапуск процесса DSH: очередь не восстанавливается (осознанно, чтобы не
  удорожать работу).
- Переполнение очереди: `QUEUE_FULL` для новой команды, принятые не страдают.

## Проверка

- `node test/queue.test.mjs` — 15 сценариев: постановка, дедупликация, `tabs` с
  `pending`, отказы документных команд, отказ вне `artifacts/`, отложенный
  `ui_panel_open`, доставка на монтировании, `bye`, переигровка после `bye`,
  проверка документа для живых и отложенных receipt, TTL, переполнение.
- `node test/client.test.mjs` — модуль клиента после пересборки бандлов.
- Всего восемь сюит, все зелёные.

| `close` живых вкладок | `applied`, `closed:true` |

Не проверено вживую: просрочка запроса (сессию открыли до истечения TTL, запрос
исполнился; поведение покрыто тестом `queue.test.mjs`, сценарий 14) и
переполнение очереди (живой прогон открыл бы 32 вкладки; покрыто тестом,
сценарий 13).

Отдельно найдено (не связано с очередью): одна вкладка, созданная отложенным
`ui_panel_open`, осталась без frame-lease (`documentId:null`, `ready:false`) даже
после активации — `act`/`query` по ней недоступны, `close` отвечает `TAB_CLOSED`,
закрывается только кнопкой вкладки. Гипотеза: `onToolFrameLoad` снимает
регистрацию в cleanup, а сохранённый iframe не даёт повторного `load`.
