# dsh-artifact-panes

Показывает артефакты рабочей папки в **штатном правом сайдбаре** DeepSeek Harness
и умеет принимать ответы из интерактивных опросников прямо в файлы рабочей папки.

## Что внутри

- Страница **Artifacts** на стартовом экране сайдбара (рядом с Workspace files):
  дропдаун со списком файлов из `<workspace>/artifacts/` (рекурсивно) и канвас;
  первый (самый свежий) артефакт открывается сам.
- Тип вкладки `artifact` (`ctx.sidebarRightTabs.register`, band `extension`) для
  адресов `dsh-resource://file/session/...` с паттернами `*.html`, `*.htm`, `*.xhtml`.
- HTML рендерится в `<iframe sandbox="allow-scripts allow-modals">` — без
  `allow-same-origin`: страница не видит origin приложения и не может читать
  чужие данные, но её собственные скрипты (фильтры, карты, опросники) работают.
- Только HTML: `.tsx` и прочий код — обычные файлы, их показывают другие вкладки.

## Умные обновления (без сброса интерактивности)

Файл на диске может меняться (скрипт-генератор, воркер, другой инструмент).
Плагин:

1. сравнивает **отпечаток содержимого** (FNV-1a по байтам), а не время/размер:
   пока байты не изменились, iframe вообще не трогается — состояние страницы
   (выбор в опроснике, позиция карты, фильтры) сохраняется;
2. опрашивает файл раз в 5 секунд (и только когда вкладка видима);
3. при **реальном** изменении не перезагружает страницу сам: показывает бейдж
   `new` и кнопку **Применить** — вы решаете, когда применить обновление.
   Состояние страницы живёт до нажатия;
4. страница может сама попросить «живой» режим — тогда изменения применяются
   автоматически, но всё равно только по факту смены байтов:

```html
<meta name="dsh-live" content="auto">
```

Для дашбордов/табло это удобно; для опросников и карт — не включайте.

## Производительность при ресайзе сайдбара

Перетаскивание разделителя перерисовывает панель десятки раз в секунду.
Чтобы это не тормозило, в плагине:

- **заголовок страницы читается из первых 128 КБ и мемоизируется по байтам** —
  раньше `TextDecoder` разбирал файл целиком на каждый рендер (артефакт на
  924 КБ давал ~0,9 мс и ~1 МБ мусора на кадр);
- **элемент iframe кэшируется по URL** через `useMemo`: при ресайзе React
  получает тот же самый элемент и не трогает поддерево, документ артефакта не
  перезапускается;
- **список дропдауна мемоизируется** по `[открыт, список, текущий путь]`;
- **наведение и активный пункт живут в одной встроенной таблице стилей**
  (`.dap-trigger`, `.dap-item`, `.dap-btn`), а не в JS-состоянии: движение мыши
  по списку больше не вызывает ни одного рендера React;
- **повторное сканирование библиотеки раз в 6 с** сравнивает результат и не
  обновляет состояние, если на диске ничего не изменилось;
- **На время жеста штатного разделителя `[data-side="rightbar"]`** плагин
  фиксирует размер viewport iframe и отключает его `pointer-events`.
  Сама граница панели перемещается штатно; содержимое временно обрезается,
  а после отпускания iframe один раз подстраивается к итоговой ширине.
  `pointercancel`, потеря захвата, потеря фокуса и размонтирование также
  восстанавливают размер. Обработчика `pointermove`, `ResizeObserver` панели
  и таймера на каждый новый размер больше нет;
- **Неактивный слой аннотаций не измеряет панель при рендере**. Его портал
  и текущая сессия сверяются существующим узким наблюдателем атрибутов;
  геометрия нужна только видимой подсказке или уведомлению. Обработчики
  скролла и наблюдение за размером панели включаются только в режиме аннотаций;
- **Колбэки композера сохраняют идентичность для одного контроллера**,
  поэтому `AnnotationDockMemo` пропускает обновления, вызванные шириной панели;
- **Зона захвата правого разделителя — 14 px**: нейтральная полоса в покое,
  цвет текущей палитры при наведении и более выраженный цвет во время жеста.
  Штатные захват указателя и ограничения ширины сохранены; в полноэкранном
  и свёрнутом состоянии ручка отсутствует;
- все статические стили вынесены в константы модуля, чтобы не создавать
  сотни объектов на каждый рендер.

## Аннотации в правой панели (как в Codex)

Кнопка аннотаций живёт в **шапке правой панели** и видна на любой вкладке:
Artifacts, Files, Browser, Terminal, Start. Аннотация не отправляется сразу:
«Сохранить» складывает её в композер, а общий текст и все аннотации уходят
одним сообщением.

1. **Чип внутри поля ввода.** Чип «N аннотаций» вставляется **первым
   ребёнком `.GRgSLq_scroll`** (`data-input-scroll="true"`), перед
   `.GRgSLq_grow` с `contenteditable`, а не на уровне карточки и не
   оверлеем. Внутри скролла он `position:sticky; top:0`, а вокруг него —
   **только** `padding: 0 0 12px` (без верхнего/боковых отступов); текст
   начинается **ниже чипа по y**, а не уходит под него по z.
2. **Список.** Клик по чипу открывает список, выровненный по нижней кромке
   карточки: `bottom = innerHeight - chipTop + 8`, поэтому список растёт
   вверх от чипа, а не висит высоко над панелью. Наведение на чип тоже
   открывает список (через 130 мс).
3. **Карточки списка** показывают номер (совпадает с номером пина), цель,
   фрагмент текста, комментарий и миниатюру скриншота. Карандаш, ✕ и
   «Очистить» — правка/удаление. Наведение на карточку подсвечивает её и
   отправляет в iframe `{type:'dsh-annotation-highlight', id}`: пин
   увеличивается, вокруг цели рисуется рамка. Обратно: наведение на пин
   отправляет `dsh-annotation-hover`, и соответствующая карточка получает
   `data-hover`.
4. **Карандаш не редактирует в списке.** Он закрывает список и через
   `dsh-annotation-edit` открывает **ту же карточку создания у пина**
   (anchor = правый верхний угол rect), предзаполненную комментарием.
   «Сохранить» в ней обновляет существующий объект, а не создаёт новый.
5. **Общий текст + Enter/Send.** Pending-объекты кодируются в
   `<<<DSH_ANNOTATIONS>>>` + JSON + `<<</DSH_ANNOTATIONS>>>`; композер
   отправляет текст с блоком через `actions.setDraft` + `actions.submit`.
   В чате/очереди UserText-правило `dsh-annotations` рендерит карточки,
   модель получает JSON с комментариями, селекторами и путём к скриншоту.
6. **Скриншот.** При сохранении аннотации карточка на ~80 мс скрывается,
   хост снимает область цели и возвращает путь. Кнопка «Скриншот» в карточке
   позволяет переснять. Скриншоты лежат в
   `.dsh/artifact-panes/shots/`; в блоке есть поле `screenshot`, в карточке
   чата — миниатюра через GET `/artifact-panes/shot?path=...`. Агент может
   открыть PNG по пути (например, `read_image`).

### Производительность и анимации

- Inline host: MutationObserver только на прямой `childList` скролла плюс
  редкая сверка раз в 1.2 с; body-subtree observer убран.
- Overlay: body-observer только по атрибуту `data-sidebar-right-open` плюс
  сверка раз в 1.5 с; `chromeRect` обновляется только для fallback без
  ReactDOM. Пересчёт блокеров и scroll-tick — только при активном
  annotation mode, поэтому стриминг чата и ресайз панели не ререндерят
  оверлей.
- Маркерный interval вообще не запускается, если маркеров нет.
- `AnnotationDock` обёрнут в `React.memo` и не перерисовывается на каждый
  ввод текста: `input` больше не используется, актуальный черновик читается
  через `getDraft()` в момент отправки.
- Hover: у чипа, триггера и попапа нет translate/scale; карточка плавно
  меняет border/background/box-shadow, пин — фон и box-shadow; focus-box
  появляется без анимации, чтобы не было промежуточных состояний.
- Дивайдер: на hover ручки снимается full-window screenshot; при drag
  показывается замороженный screenshot + заливка (22% brand при расширении
  влево, 22% danger при сужении вправо) + прокси-линия; на отпускании
  crossfade с лёгким bounce. Это визуальный слой: нативный reflow продолжается
  под оверлеем; per-element FLIP не делается. Preview-скриншоты
  `preview-*.png` перезаписываются.

### Хост-маршруты

- `POST /artifact-panes/screenshot` — `{rect:{x,y,w,h},padding}`; запускает
  `shot.ps1` (PrintWindow + ClientToScreen + crop), пишет PNG, возвращает
  `{ok, path}`.
- `GET /artifact-panes/shot?path=.dsh/artifact-panes/shots/<file>.png` —
  отдаёт PNG только из каталога shots.

Маршруты добавляются хост-плагином; после изменения `index.js` нужен
перезапуск/перезагрузка плагина (в этой итерации — `plugin_manager.set_bundle`
disabled → enabled). Без перезагрузки клиент получает 404 на скриншот и
сохраняет аннотацию без изображения.

### Проверка

Живая проверка: попап открывается у чипа (bottom-aligned, не высоко);
карточка содержит миниатюру скриншота; номер пина на артефакте совпадает;
авто-скрин при сохранении создал PNG; хост-маршруты отвечают 200; скриншот
отдаётся через `/artifact-panes/shot`. Отправка текста + аннотаций и рендер
карточек в очереди проверены ранее. Цель вставки чипа изменена на
`[data-input-scroll="true"]` (`.GRgSLq_scroll`) по присланному HTML; после
следующей pending-аннотации её нужно проверить визуально — тестовое
сохранение в этой итерации не прошло. Правка через карандаш и переход к
карточке у пина реализованы; live-проверка карандаша не завершена.

### Ограничения

- Скриншот — это кроп окна DSH; окно должно быть видимым (не свёрнутым) и не
  перекрытым другим окном. Кросс-доменный iframe не читается из JS, поэтому
  используется нативный PrintWindow.
- Маркеры и подсветка пинов работают в HTML-артефакте; на Files/Browser чип и
  список работают, маркеров на странице нет.
- При ошибке хоста аннотация сохраняется без скриншота; путь можно переснять
  кнопкой.

## Ответы из опросников

Страница в iframe не может писать файлы, поэтому всё идёт через `postMessage` →
клиент плагина → host-маршруты:

| маршрут | что делает | файл |
| --- | --- | --- |
| `POST /artifact-panes/draft` | автосохранение каждого выбора | `.dsh/artifact-panes/drafts/<requestId>.json` (перезаписывается) |
| `POST /artifact-panes/answer` | финальный ответ по кнопке | `.dsh/artifact-panes/answers/<время>-<requestId>.json` |
| `GET /artifact-panes/state?requestId=…` | что восстановить при загрузке | берёт самый свежий из двух |

Черновик — это и есть страховка от перезагрузок: каждый клик переписывает один
и тот же файл, так что перезапуск DSH или F5 больше не обнуляют опросник.
При загрузке страница объявляет себя (`dsh-artifact-ready`), плагин отдаёт
сохранённые ответы (`dsh-artifact-restore`), и выбор восстанавливается.

Контракт со стороны артефакта:

```js
// при загрузке — попросить восстановление (плагин ответит restore)
window.parent.postMessage({ type: 'dsh-artifact-ready', requestId: 'decision-route-2026-11' }, '*');

// на каждое изменение — черновик
window.parent.postMessage({ type: 'dsh-artifact-draft', requestId: 'decision-route-2026-11', answers }, '*');

// по кнопке — финальный ответ
window.parent.postMessage({ type: 'dsh-artifact-answer', requestId: 'decision-route-2026-11', answers }, '*');
```

Клиент принимает сообщения только от своего iframe (`event.source`) и отвечает:

```js
{ type: 'dsh-artifact-restore', requestId: '…', kind: 'draft' | 'final', answers: { … } }
{ type: 'dsh-artifact-ack', kind: 'draft' | 'final', ok: true, path: '<файл>' }
```

Канал установлен в обеих вкладках: и в странице Artifacts, и в читалке файла
(артефакт можно открыть из дерева файлов или из транскрипта — ответ всё равно
дойдёт). В шапке вкладки на время показывается статус «Ответ отправлен агенту».

Опросник показывает «Отправлено» только после подтверждения; черновик
подтверждается строкой «Черновик сохранён в HH:MM». Если host не ответил за
6 секунд на финальную отправку, кнопка становится «Повторить отправку», а JSON
ответов остаётся в блоке «Показать JSON ответов» — данные не теряются.

Проверки без запуска DSH: `node test/host.test.mjs` (все четыре маршрута на
временном workspace), `node test/survey.test.mjs` (страница опросника: ready →
restore → черновик → финальный ответ на DOM-заглушке), `node test/client.test.mjs`
(регистрация, рендер, выбор артефакта в дропдауне), `node test/csp.test.mjs`.

Готовый образец: `<workspace>/artifacts/templates/decision-survey.html` —
опросник с вариантами, подсказками по trade-offs, живой сводкой и отправкой.
Скопируйте его, замените `SURVEY` и `requestId` — получится новый опросник.

## Установка

`dsh plugin --profile desktop add <путь-к-папке-пакета>` (или Plugins → Add plugin).
Удаление: `dsh plugin --profile desktop remove dsh-artifact-panes`.
